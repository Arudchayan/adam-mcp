## Installed package and student-approved direct journey

The 0.4.0 tarball was installed with production dependencies in a fresh consumer
outside Git, using an isolated dedicated Chrome profile. Help and setup preview
ran without changing persistent client configuration. Initial passive status
reported login-required. A sign-in timeout and a user-closed-window cancellation
returned actionable errors. A later student-completed SWITCH sign-in verified
ADAM and handed off to the background session.

An independent agent drove an actual raw JSON-RPC stdio client against that
installed executable. Initialization reported server version 0.4.0 and negotiated
protocol 2025-03-26. It listed 14 tools, one static resource and eight courses.
Status remained signed in across fresh stdio client startup. Omitted confirmation
returned confirmation_required; false confirmation failed schema validation.
Neither refusal returned a body. Tool-name inspection and advertised test-denial
policy were checked; this is not a new runtime proof of every denied operation.

The student subsequently approved one selected course-overview read. The installed
server returned 7,632 text characters with `untrusted: true` and a notice. No body,
course identity, credentials, profile or raw response is committed in this record.

## Shutdown blocker found and resolved by the journey

The independent harness saved its results but did not terminate after stdin EOF.
A separate selected-read harness reproduced the issue: no process exit within
five seconds after EOF; its own spawned server was then terminated by signal.
Source review confirmed configured-provider cleanup was missing on EOF. The focused
fix (ADR 0044), through `cbc664d85aa14b4ee034c96116d8ad24f25a806e`, was implemented
by Luna, personally reviewed by the coordinator and independently reviewed by Terra.
Review found and resolved recoverable-message handling, startup/cleanup rejection
and initialization/shutdown ordering bugs before integration. The MCP suite passed
236 tests and typechecking at that snapshot.

A newly packed and separately installed consumer with that fix completed the direct
journey. Connected status and eight-course listings succeeded both before and after
client restart; omitted-confirmation reads were refused. Both clients exited on
stdin EOF with code zero, without a termination signal. Explicit CLI logout of the
isolated profile succeeded. A subsequent fresh client reported disconnected status
and unauthorized course listing, then also exited normally on EOF. No additional
body reads were performed during that recheck. Other profiles were not logged out.
