## Installed-client walkthroughs (independent Claude chats, counts only)

1. **First 0.5.0 run.** It accidentally used a stale 0.4.0 server process that the desktop app had kept after the reinstall: 18 tools, no `adam_list_notes`, no item groups. Its results were discarded. The app was restarted to load 0.5.0.
2. **Second run (`a440de0`).** Every step passed, but unscoped calendar and news stayed `partial` on the retry, which came more than a minute later. Fixed in #180 (ADR 0061 amendment): budget-limited walks finish in the background, and joining calls are bounded.
3. **Final run (`3d18e09`, the published bytes).** All steps passed:
   - 19 tools, including `adam_list_notes`. Signed in before and after.
   - 8 courses. Children: 66 in total, including 5 item groups.
   - A read without approval returned `confirmation_required`; the approved read returned `untrusted: true` text with no `detail` for a course.
   - Calendar and news: partial on the first pass (`time_budget`) and **complete** on the later pass.
   - Mail: 8 unread, no label prefixes.
   - Notes: `confirmation_required` without approval, then `empty` with it.
   - Exercise detail: no peer review.
   - Course members: `forbidden`.

Explicit logout was not repeated. The CLI logout path is unchanged since the 0.4.0 record.
